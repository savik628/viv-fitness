# Правила разработки и взаимодействия проекта VIV (GEMINI.md)

## 1. Язык и стиль общения (Экономия токенов и времени)
- **Язык:** Исключительно русский язык во всех ответах, рассуждениях и комментариях.
- **Лаконичность и фокус:** Отвечать строго по делу. Без вводных вежливых фраз («Конечно!», «С радостью сделаю...», «Отличный выбор!»).
- **Формат отчета о выполнении:**
  1. Краткий статус (1–2 предложения о результате).
  2. Кликабельные ссылки на изменённые файлы: `[файл.js](file:///полный_путь#L10-L20)`.
  3. Краткий список изменений (маркеры).
- **Никаких дублей кода в чате:** Не выводить в чат файлы целиком или большие простыни кода, если они уже сохранены в проекте.
- **Формат контента:** Только лаконичный Markdown-текст, списки и таблицы. Не использовать генерацию картинок и схем, если пользователь явно об этом не просил.

## 2. Эффективная работа с кодом и инструментами
- **Точечное чтение:** При использовании `view_file` ВСЕГДА указывать `StartLine` и `EndLine` (30–80 строк). Не читать файлы целиком без прямой необходимости.
- **Точечное редактирование:** Использовать `replace_file_content` с минимальным окном заменяемых строк. Не переписывать файл целиком, если меняется отдельный блок.
- **Автоматическая валидация:** После правки JS-файлов ВСЕГДА запускать `node -c <файл>` для мгновенной проверки синтаксиса до ответа пользователю.
- **Синхронизация кэша PWA:** При любых правках клиентского кода (`js/`, `css/`, `index.html`) автоматически инкрементировать версию кэша в `sw.js` (`CACHE_NAME = 'viv-core-v1.0.X'`), гарантируя немедленное обновление у пользователя в браузере.

## 3. Выполнение терминальных команд (macOS / Google Drive)
- **Прямой запуск Google Drive:** Проект расположен в каталоге CloudStorage Google Drive. Стандартная песочница блокирует к нему доступ (`Operation not permitted`). Поэтому все рабочие команды (`git`, `node` и т.д.) запускать сразу с `BypassSandbox: true`, исключая потерю шагов и времени на повторы.
- **Пакетные операции Git:** При запросах «загрузи в гит», «сделай пуш» и т.п. выполнять команды единой цепочкой:
  `git add <файлы> && git commit -m "<описание>" && git push origin main`
  и сразу выводить хэш коммита и ссылку на GitHub Pages: `https://savik628.github.io/viv-fitness/`.

## 4. Архитектурный контекст проекта VIV
- **Стек технологий:** Чистый Vanilla JavaScript (ES6 модули/скрипты), HTML5, CSS3, Service Worker (PWA offline), LocalStorage / IndexedDB. Без фреймворков и сборщиков.
- **Дизайн-система:** Премиальный стиль Apple Fitness & Nike Athletic:
  - Тёмная палитра: глубокий фон `#0d0f12`, карточки `#14181c`, границы `#1c2229`.
  - Акценты: неоновый лайм `#DFFF00` / `#ccff00` и спорт-изумруд `#00F59B`.
  - Типографика: SF Pro Display / Inter / system-ui, жирные контрастные цифры метрик.
  - Адаптивность: строгий запрет на горизонтальный скролл (`overflow-x: hidden`), полная адаптивность для экранов от 360px.
- **Целостность существующего кода:** Не удалять и не модифицировать несвязанный функционал, комментарии и настройки без прямой просьбы пользователя.
